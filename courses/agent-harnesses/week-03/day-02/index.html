Run And Summarize Development Results

By the end of this hour

  • Run the eight-task development suite from clean workspaces.
  • Explain failures using trace-linked evidence.

Before you begin

  • Use eight validated development fixtures and the event/replay tools.

Environment or workflow question? Day 0 handbook.

The key idea

A development report is a debugging instrument, so make failed runs visible and traceable. Record both task-level success and harness-level termination for every attempted task. A timeout, denied request, or infrastructure error cannot disappear from the denominator merely because it was inconvenient. At this stage, deterministic scripts are still legitimate integration controls; any live-model results must be labeled separately with the model configuration. Keep final-task agent outcomes unopened so the development set remains the place where tool and prompt changes are made.

Your 60-minute plan

  1. Retrieve

    5 min

    For eight attempted tasks with one infrastructure failure, what denominator should the end-to-end completion rate use?

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 5 minutes on H4: Interpret outcomes alongside transcripts. Spend 5 minutes on H19: Evaluation measurements beyond task accuracy. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Run all eight development fixtures through the suite runner with the current configured model mode. Use deterministic scripts where that is your existing baseline and label them clearly. Collect task id, model mode, run id, terminal status, grade, elapsed time, cost provenance, and trace path. Group unsuccessful runs by the earliest supported cause: task misunderstanding, bad edit, tool/interface issue, budget limit, or infrastructure. Write reports/dev-v1.md with the result table and two short trace analyses. Make no changes based on final-task agent outcomes.

  4. Verify and save

    10 min

    Verify that every attempted task appears in the table and every row links to a saved trace. Save the exact code revision and configuration next to the report.

What to save

Development report links outcomes to traces.

Watch for: A scripted integration pass rate must not be presented as live-model task performance.

Check your understanding

Why report protocol termination separately from the task grade?

Check your reasoning

A normal final answer can accompany a wrong workspace, while a tool or infrastructure error explains a different failure mode. Both are needed to understand reliability.
