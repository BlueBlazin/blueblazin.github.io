Complete Eight Development Task Fixtures

By the end of this hour

  • Complete eight small development fixtures.
  • Validate each grader with a reference solution and broken or no-op control.

Before you begin

  • Use the 24-task manifest and dev-01 through dev-03 from Activity 2.
  • Keep graders and reference solutions in host-only evaluation storage.

Environment or workflow question? Day 0 handbook.

The key idea

A grader must reject known failures as well as accept a correct answer. Otherwise a passing run may reflect a weak check rather than a successful agent. Reference controls establish that the task is solvable in the configured environment; no-op controls establish that leaving the initial state unchanged is not sufficient. Choose small development tasks that expose different harness behaviors while staying within today’s hour. A narrow, well-tested fixture is more useful than a large repository task whose expected behavior you cannot inspect.

Your 60-minute plan

  1. Retrieve

    5 min

    Explain how a grader that only checks whether a file exists could incorrectly pass an unchanged task.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 5 minutes on H4: Concrete success requirements and negative grading controls. Spend 5 minutes on H17: Parametrized control tests with descriptive case IDs. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Add dev-04 through dev-08 as small fixtures: a boundary-condition bug, a missing configuration key, a data-filtering error, a renamed interface call, and a multi-file consistency change. Reuse the fixture template rather than building five new frameworks. For every development task, store a known-correct reference patch plus the unchanged initial state and, where easy, one plausible wrong patch. Run its host-side grader on each control. If time is tight, reduce fixture size while retaining the required behavior and all eight validated task ids.

  4. Verify and save

    10 min

    Save eval/control-results.json with eight rows showing reference pass and no-op/broken fail. Repair any permissive grader before using that fixture for agent results.

What to save

Eight fixtures reject broken/no-op solutions.

Watch for: Do not add extra hidden requirements to the grader that are absent from the task request.

Check your understanding

What should you do when both the reference solution and no-op state pass?

Check your reasoning

Treat the grader as invalid for that task until repaired. The current check cannot distinguish the requested improvement from doing nothing.
