Bound Process Time And Output

By the end of this hour

  • Stop task execution at a wall-time limit.
  • Bound output collection and terminate excessive-output runs.

Before you begin

  • Use the isolated command runner from Activity 3 and keep tests confined to disposable fixtures.

Environment or workflow question? Day 0 handbook.

The key idea

Execution limits must constrain work and resource collection, not just the amount printed in a final report. Capturing all output in memory and truncating afterward still allows excessive memory use. Likewise, timing out the caller while leaving the command running does not enforce a wall-time budget. Choose explicit limits for this exercise and record what happens when they are reached. Terminate the container or relevant process group, wait for it to exit, and distinguish timeout from output-limit failures in the tool result.

Your 60-minute plan

  1. Retrieve

    5 min

    Explain why slicing a captured output string to 4 KB after a command finishes is not an output-collection limit.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H13: Popen termination, wait, and output-buffering caveats. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Add a short configurable wall-time cap and a cumulative stdout-plus-stderr byte cap to harness/runner.py. Read output incrementally or use an execution API with equivalent enforced limits. On either breach, stop the whole task execution unit and confirm termination; preserve only a bounded output prefix and a structured reason. Add two tiny Python fixture commands: an endless sleep loop and a loop printing fixed-size lines. Keep limits small so the tests finish quickly. Record elapsed wall time, collected bytes, exit status, and termination reason.

  4. Verify and save

    10 min

    Run both fixtures twice. Confirm time stays within the cap plus a documented cleanup allowance and that retained output never exceeds the chosen byte limit.

What to save

Both processes stop within documented limits.

Watch for: Killing only the immediate child can leave descendants running; terminate the execution unit your boundary promises.

Check your understanding

Why should cleanup time be reported separately from the requested time limit?

Check your reasoning

Termination and resource cleanup take time after the deadline. Reporting both makes the effective end-to-end bound observable rather than implying an instantaneous stop.
