Enforce Paths And Tool Authorization

By the end of this hour

  • Authorize tool requests in host code before execution.
  • Reject resolved path escapes and unsupported network requests.

Before you begin

  • Use the runner and documented boundary from Activity 3, step 1.
  • Retain the shared workspace path resolver from Activity 2.

Environment or workflow question? Day 0 handbook.

The key idea

Authorization decides whether a valid request is allowed in this run; validation only decides whether it matches the request schema. Enforce both before dispatch. A file path can escape through a parent component or a symlink, so check the resolved target’s ancestry rather than a string prefix. For new files, resolve existing parent directories and enforce the same boundary. These checks complement the container’s filesystem restrictions. They do not make arbitrary concurrent filesystem manipulation safe, so keep this course runner limited to controlled disposable tasks.

Your 60-minute plan

  1. Retrieve

    5 min

    Give one schema-valid request that your harness should still refuse. Identify the code layer that must make that decision.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H12: Resolved paths, parent paths, and is_relative_to limitations. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Add a host-side allowlist to each run configuration and require authorization before invoking a tool. Extend path handling to reject absolute paths, parent traversal, symlinks resolving outside the task root, and writes through an escaping parent symlink. Create temporary symlink fixtures pointing to a harmless outside canary. Refuse network tools unless explicitly supported; keep task networking disabled in the runner. Add dispatch counters to demonstrate denial occurs before side effects. Document that tools operate sequentially on controlled fixtures, without claiming race-free hostile filesystem handling.

  4. Verify and save

    10 min

    Run the traversal, symlink, unauthorized-tool, and unsupported-network cases. Save an authorization matrix showing request, rejection category, and zero side-effect confirmation.

What to save

Boundary rejection cases pass.

Watch for: Resolving only the final filename is insufficient when a parent directory is a symlink outside the workspace.

Check your understanding

Why do you need authorization if tool arguments already pass validation?

Check your reasoning

A correctly formed request may still exceed the permissions of the current run. Validation checks shape and values; authorization checks whether this actor and run may perform the action.
