Run Three Fixtures End To End

By the end of this hour

  • Run three development tasks through the complete loop.
  • Diagnose failures from verified outcomes and traces.

Before you begin

  • Use dev-01 through dev-03, their outcome checks, and scripted FakeModel responses.

Environment or workflow question? Day 0 handbook.

The key idea

End-to-end execution connects the request, tool interface, loop, workspace mutation, and grader. This first run is an integration check, not a measure of model capability: scripted responses deliberately exercise known paths. The important distinction is between a harness that completes its protocol and a task whose final state satisfies the grader. Save both statuses. A trace should let you locate the first divergence, such as a malformed argument, a missing observation, or an edit to the wrong file, without rerunning an expensive model.

Your 60-minute plan

  1. Retrieve

    5 min

    Predict which fields distinguish a completed loop with an incorrect edit from a loop stopped by an exception.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H14: Iterable side_effect and call assertions. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Write a small development runner that copies a fixture, supplies its request to run(), collects the final state, and invokes the host-side grader. Add one FakeModel script per development task using read/search/write tools as appropriate. Run all three from fresh copies. If a run fails, classify whether the fixture, tool contract, loop, or proposed edit caused it before making a narrow correction. Save a machine-readable row per run with task id, protocol status, outcome status, elapsed time, mock cost, and trace path.

  4. Verify and save

    10 min

    Run all three tasks again after fixes. Save results/dev-smoke.json and link each result to a complete trace; confirm no final task was executed.

What to save

Three complete runs with outcome, time, and cost.

Watch for: Reusing the already repaired workspace can produce a false success without any useful action.

Check your understanding

Can three passing scripted runs be described as a model success rate?

Check your reasoning

No. They validate the harness integration using predetermined actions. Model capability requires actual model trials under a documented evaluation protocol.
