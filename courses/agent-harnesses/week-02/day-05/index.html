Environment or workflow question? Day 0 handbook.

The key idea

A boundary is credible when its claims match repeatable tests and its limitations remain visible. Test both allowed behavior and denied behavior: a harness that rejects everything is safe in a narrow sense but unusable. Group failures by mechanism so a passing path check is not mistaken for network isolation or process cleanup. These tests establish the behavior of your configured development environment on controlled cases. They do not prove a general-purpose sandbox is secure against arbitrary hostile workloads or kernel vulnerabilities.

Your 60-minute plan

  1. Retrieve

    5 min

    Without looking at tests, list the boundary claims you can currently support and one claim you cannot support.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 5 minutes on H17: Parametrize the supported boundary cases. Spend 5 minutes on H10-security: Compare tested claims with the runtime security scope. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Create tests/test_execution_boundary.py as a compact parametrized matrix. Include an allowed read/write command, traversal, outside symlink, write through outside parent symlink, denied tool, denied network access, infinite process, excessive output, and missing credential canary. Assert both the returned category and absence of the prohibited effect. Add docs/execution-boundary.md with actual mounts, environment, networking, limits, cleanup behavior, and known limitations. If any claimed isolation check is unsupported by your current runner, record a failing or blocked gate instead of weakening the expected result.

  4. Verify and save

    10 min

    Run the complete matrix from a clean task workspace. Save the result summary and confirm docs/execution-boundary.md contains only guarantees supported by the implementation and tests.

What to save

Automated boundary matrix passes.

Watch for: Do not skip a failing isolation test and still label the entire boundary complete.

Check your understanding

What does a passing boundary matrix establish, and what does it not establish?

Check your reasoning

It establishes the configured runner’s behavior on the tested cases. It does not prove complete security for arbitrary hostile code or replace the underlying container/OS security model.
