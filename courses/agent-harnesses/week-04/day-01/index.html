Implement Bounded Repository File Listing

By the end of this hour

  • Provide deterministic bounded file listings.
  • Choose development tasks that require navigation decisions.

Before you begin

  • Use the confined workspace tools and shared development evaluator.

Environment or workflow question? Day 0 handbook.

The key idea

Navigation tools shape which parts of a repository a model can discover. A deterministic listing makes tool behavior inspectable and avoids irrelevant filesystem ordering noise. Bound the number of entries and state whether more remain; exclude known non-source directories only through a documented policy. A useful navigation task requires finding evidence, not simply editing a filename already given in the prompt. Start with tiny repositories where you know the relevant file set, so omissions can be evaluated directly rather than guessed from a failed answer.

Your 60-minute plan

  1. Retrieve

    5 min

    What information is lost when a listing returns only the first fifty filenames without saying that more exist?

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 5 minutes on H12: Directory iteration, ordering, and symlink choices. Spend 5 minutes on H3-paper: Agent-computer interface choices for navigation. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Implement list_files with a relative root, stable lexical ordering, and an explicit maximum entry count. Return entries plus truncated and total_seen or another honest indication of incompleteness. Reuse path authorization and define how hidden files, symlinks, and generated directories are handled. Select two existing development tasks where the relevant edit or dependency is not named directly. Add a few harmless distractor files if needed, version that fixture change, and preserve the task’s original behavior and grader. Record the known relevant filenames in host-only analysis notes.

  4. Verify and save

    10 min

    Run listing tests on an empty directory, a nested fixture, and a fixture over the limit. Save the tool contract and selected development task ids.

What to save

Bounded listings on selected repositories.

Watch for: Excluding generated-looking directories can hide real task evidence; document and test the exclusion policy.

Check your understanding

Why record relevant filenames outside the agent workspace?

Check your reasoning

They are evaluation evidence about navigation quality. Exposing them to the agent would remove the discovery problem being studied.
