Combine Search With Selected File Reads

By the end of this hour

  • Connect exact search to bounded selected-file reads.
  • Expose omitted evidence in navigation traces.

Before you begin

  • Use bounded listings and the exact-search/read tools from Activity 2.

Environment or workflow question? Day 0 handbook.

The key idea

Search and selected reads are a simple context-selection pipeline: search narrows candidate locations, then small reads supply enough surrounding evidence to act. Each truncation changes what the model can know. A search that stops after a fixed number of matches should disclose that later matches were omitted; a file read should disclose the requested and returned line ranges. Preserve these facts in traces so a later failed edit can be linked to missing evidence instead of being vaguely attributed to poor reasoning.

Your 60-minute plan

  1. Retrieve

    5 min

    For a matched function name, explain why its matching line alone may not reveal the required edit.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H19: Response context and token-efficient outputs. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Extend exact_search to return path, matching line number, a bounded text excerpt, and a truncation indicator. Add read_lines(path, start, count) with documented line numbering and a maximum returned span. Keep the existing byte cap as a second bound. Include requested range, returned range, and omitted-count metadata when known. Script a search-to-read example where the first excerpt lacks a required nearby definition, then retrieve that definition explicitly. Log selected paths and ranges so later analysis can distinguish absent repository evidence from evidence that existed but was never returned.

  4. Verify and save

    10 min

    Save a navigation trace with one truncated search and one partial file read. Verify the model-visible output and saved metadata both identify incompleteness.

What to save

Navigation traces show truncation and selected evidence.

Watch for: Do not state an exact omitted count if the search stopped before counting all remaining matches.

Check your understanding

What is the difference between evidence absent from the repository and evidence omitted by context selection?

Check your reasoning

Absent evidence cannot be retrieved from that snapshot. Omitted evidence was available but the tool or policy failed to include it, making it a navigation/context-policy issue.
