Environment or workflow question? Day 0 handbook.

The key idea

A trial manifest is the bridge between a study design and an auditable execution. Each row should identify one task, condition, and repeat before the runner starts. Stable IDs make partial progress and interrupted jobs visible, and prevent successful retries from overwriting unsuccessful attempts. The manifest must resolve to the frozen code and grader versions rather than whatever happens to be checked out. Preparing this table requires no agent calls and can catch missing combinations, mismatched budgets, or accidental development tasks before evaluation begins.

Your 60-minute plan

  1. Retrieve

    5 min

    Compute the number of trials per repeat and for the complete study. State which outcomes remain in the table even when unsuccessful.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 5 minutes on H21: itertools.product for the trial Cartesian product. Spend 5 minutes on H28: Transaction boundaries for a shared reservation ledger. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Generate the Cartesian product of sixteen final task IDs, two condition IDs, and repeat indices one through three. Assign stable trial IDs and include frozen code/config/task references, per-trial limits, output directory, and initial status. Assert exactly 96 unique rows, 32 per repeat, and six per task. Dry-run manifest resolution and fresh-workspace creation without model calls. Check the remaining budget against the predeclared estimate and verify that the global stop rule is active. Save the intended balanced or randomized execution order before observing outcomes. Start with study concurrency one. Before allowing parallel trials, use a single transactional reservation ledger for the shared study cap; a separate local balance in each worker can overspend. Persist reservations and unknown-usage states across runner restarts.

  4. Verify and save

    10 min

    Commit or archive the immutable trial manifest and dry-run report. Confirm every trial can be linked back to the frozen experiment record.

What to save

Manifest contains exactly 96 scheduled trials.

Watch for: Do not let a resume command regenerate a different trial manifest from changed defaults.

Check your understanding

Why assign trial IDs before execution?

Check your reasoning

They preserve the denominator and make missing, interrupted, failed, and successful attempts traceable without outcome-driven renaming or replacement.
