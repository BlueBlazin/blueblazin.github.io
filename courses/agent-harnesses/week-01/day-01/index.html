Build the First Bounded Agent Loop

By the end of this hour

  • Implement a tiny FakeModel loop with a host-owned step limit.
  • Represent success and budget exhaustion as explicit terminal results.

Before you begin

  • Complete only the Day 0 readiness checklist: local repository, Python environment, and passing smoke test. No paid model or prior agent implementation is required.

Environment or workflow question? Day 0 handbook.

The key idea

An agent harness is ordinary software that repeatedly gives a model context, interprets its response, and decides whether to call a tool or stop. The model proposes actions; the host program owns execution and limits. Representing this as a state machine makes error paths visible before an API is involved. A useful initial design has waiting-for-model, validating-call, running-tool, and terminal states. Observations become messages for the next model turn. You need observable actions and results, not access to a model’s private reasoning.

Your 60-minute plan

  1. Retrieve

    5 min

    Without reading, sketch what happens after a model asks to read a file. Mark which component is allowed to execute the read.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 6 minutes on H2: Agents section: feedback loop and host stopping conditions. Spend 4 minutes on H1: Abstract and approach: actions followed by observations. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Create harness/loop.py with a small RunState record: task, messages, response count, maximum responses, and terminal result. Write a minimal run() that consumes scripted dictionaries from a FakeModel iterator: an observe response appends a supplied observation, while a final response returns an answer. Check the response allowance before requesting another response. Run a two-observation-then-final script and an endless-observation script capped at three responses. Add assertions for exact response counts and terminal statuses. Sketch the state transitions in docs/loop-contract.md after the code runs. Keep this stub deliberately small: strict typed calls, real tool dispatch, exceptions, and timeouts are the next three lessons.

  4. Verify and save

    10 min

    Run both scripts twice, confirm deterministic counts, and save the code plus two assertions. Verify no transition from a terminal result requests another response.

What to save

Working loop plus successful and capped transcript tests.

Watch for: A terminal answer is an output, not proof that the requested task was actually solved.

Check your understanding

Why should the host enforce the step budget even when the prompt asks the model to stop?

Check your reasoning

The prompt influences a model response; it cannot guarantee termination. The host owns the loop and can refuse another iteration independently of what the model requests.
