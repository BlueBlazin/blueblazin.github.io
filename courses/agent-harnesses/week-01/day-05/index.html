Build Confined Workspace Read Tools

By the end of this hour

  • Implement deterministic read and exact-search tools in one workspace.
  • Reject paths that leave the disposable workspace.

Before you begin

  • Use the validated tool dispatcher from Activity 1; create a temporary fixture directory with a few text files.

Environment or workflow question? Day 0 handbook.

The key idea

Repository tools should reveal useful evidence through small, predictable interfaces. Start with explicit relative paths and exact substring search, returning filenames and line numbers instead of entire repositories. Resolve the workspace root and requested paths before reading, then require the resolved path to remain under the root. This is an application boundary for a trusted disposable fixture, not a complete defense against hostile concurrent filesystem changes. Keep command execution mocked until the isolation activity establishes a separate execution boundary.

Your 60-minute plan

  1. Retrieve

    5 min

    Name the difference between rejecting a path containing two dots and verifying the final resolved path belongs to the workspace.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 6 minutes on H12: Path.resolve and ancestry checks; symlink behavior. Spend 4 minutes on H19: Tool outputs that return useful bounded evidence. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Create harness/workspace.py with a shared resolve_path(root, relative_path) helper. Implement read_file with an explicit byte cap and exact_search with a fixed maximum number of matching lines. Return structured fields for path, line number, text, and truncation. Create fixtures containing one match, multiple matches, and a missing path. Reject absolute paths and resolved escapes. Add a command tool stub that returns unsupported without executing anything. Keep accepted files as small UTF-8 text and state this restriction in the tool descriptions.

  4. Verify and save

    10 min

    Run direct tool tests for an in-root read, exact match, missing file, and ../ escape. Save the fixture and results; verify no test accesses personal working files.

What to save

Read/search results remain inside the workspace.

Watch for: A lexical prefix check can confuse /tmp/task with /tmp/task-other; compare resolved path ancestry.

Check your understanding

Why return a truncation flag rather than silently returning the first matches?

Check your reasoning

The model and evaluator need to know the result is incomplete. Silent truncation can make absent evidence look like evidence of absence.
