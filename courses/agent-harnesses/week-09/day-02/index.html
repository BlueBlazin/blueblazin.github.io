Inspect Representative Private Task Failure Traces

By the end of this hour

  • Explain representative failures using trace evidence.
  • Distinguish observations from untested causal explanations.

Before you begin

  • Private-suite outcome and cost tables.
  • Raw traces containing context-policy events, selected evidence, and tool results.

Environment or workflow question? Day 0 handbook.

The key idea

A trace can reveal where a run lost evidence or repeated work, but one example cannot establish a general causal effect. Select a few representative failures using a stated rule, then connect observations to event IDs and task outcomes. Compare paired conditions on the same task when useful, while acknowledging model variability across repeats. Keep this analysis separate from harness changes: the final study is frozen. Good failure analysis produces bounded explanations and testable follow-up questions rather than retroactively optimizing the measured system.

Your 60-minute plan

  1. Retrieve

    5 min

    State the difference between “the evidence pointer disappeared” and “compaction caused this failure.” What additional support would the second claim need?

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H19: Trace inspection and diagnostic tool-error patterns. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Select up to three failed attempts by a reproducible rule, such as the earliest trial in each common failure category. For each, record task, condition, outcome, activation events, decisive trace range, and missing or misused evidence. Compare the other condition on the same task where useful. Include a failure with another plausible cause if one exists, but do not force that interpretation. If fewer than three failures exist, analyze all of them and fill the remaining cases with representative successes or near-budget completions. If no failures exist, state that result and analyze three successes; do not manufacture failures on the final set. Label conjectures and keep proposed changes separate from the frozen experiment.

  4. Verify and save

    10 min

    Save reports/failure-analysis.md with up to three evidence-linked failures, or the documented success-case fallback, and a statement of what the cases establish.

What to save

Trace-linked private-study failure analysis.

Watch for: Do not cherry-pick only dramatic examples that support the expected result.

Check your understanding

Why include a failure unrelated to the preferred explanation?

Check your reasoning

It prevents the report from presenting every failure as evidence for one theory and shows the limits of the measured intervention.
