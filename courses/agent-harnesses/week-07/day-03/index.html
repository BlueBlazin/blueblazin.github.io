Inject Model Timeout And Rate Limits

By the end of this hour

  • Classify model-call errors into retryable and permanent categories.
  • Verify that retries obey attempt, time, and cost limits.

Before you begin

  • The harness model adapter and budget accounting from earlier activities.
  • A fake model client or dependency injection point for deterministic tests.

Environment or workflow question? Day 0 handbook.

The key idea

Retrying can recover a transient service failure, but an unbounded retry loop turns a temporary problem into an uncontrolled run. Treat retry policy as explicit harness behavior: classify the error, check remaining limits, and record the decision. A timeout does not guarantee that the provider performed no work, so preserve uncertainty in usage accounting where applicable. Use injected responses instead of deliberately exhausting a live API. Deterministic failure sequences make it possible to test the stopping rule quickly without spending your experiment budget.

Your 60-minute plan

  1. Retrieve

    5 min

    Predict what should happen after timeout, retryable rate limit, and invalid-credential errors. Which should not be retried automatically?

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 6 minutes on H9: Retry policy, typed API errors, and timeouts. Spend 4 minutes on H14: Script transient and permanent error sequences. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Add fake model sequences for timeout-then-success, repeated retryable rate limits, and a permanent authentication or invalid-request error. Configure a small explicit retry limit and a short test deadline. Use an injectable clock or test backoff so the test does not spend the hour waiting. Assert the number of calls, final status, recorded error category, and remaining budget. Confirm retries count toward the run limits and that a permanent error stops immediately. Save the policy in a short table beside the tests.

  4. Verify and save

    10 min

    Run the cases without live model calls and save their event traces plus the retry-policy table.

What to save

Retry tests stop within configured budgets.

Watch for: Do not use a live API to manufacture rate limits when a fake adapter can test the policy.

Check your understanding

Why is a timeout not proof that a call cost nothing?

Check your reasoning

The provider may have processed a request before the response was lost or delayed. Record available usage and unresolved accounting rather than assuming zero.
