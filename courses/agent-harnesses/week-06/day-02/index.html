Verify Protocol And Permission Boundaries

By the end of this hour

  • Demonstrate the complete protocol smoke test.
  • Show that model output cannot authorize a denied tool call.

Before you begin

  • The direct-versus-MCP case matrix and saved raw examples.
  • The adapter plus the host permission enforcement code.

Environment or workflow question? Day 0 handbook.

The key idea

The final adapter check is a boundary demonstration, not a claim that the whole agent system is secure. A model can propose arguments and persuasive text, but the host must make the permission decision from trusted configuration and validated paths. The protocol must not create a shortcut around that decision. Keep evidence narrow and inspectable: a discovered tool, a permitted result, a rejected operation, and the code location responsible for each outcome. This also makes later SDK upgrades easier to review.

Your 60-minute plan

  1. Retrieve

    5 min

    State who proposes an operation and who authorizes it. Point to the trusted configuration used for the decision.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H6-tools: Tool security requirements and untrusted annotations. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Combine server startup, tool discovery, one permitted invocation, and one denied invocation into a repeatable smoke command. Add a request containing extra text or an unexpected field claiming authorization; require the host boundary to reject or ignore that claim according to your argument schema. Inspect the adapter call graph to confirm both invocation paths reach the same permission gate. Save the smallest trace demonstrating this property. Document the transport and local-only deployment scope actually tested rather than claiming a production-ready MCP service.

  4. Verify and save

    10 min

    Run the smoke command from a fresh process, then commit the adapter, contract table, tests, and a short supported-scope note.

What to save

Smoke test passes with external permission enforcement.

Watch for: A passing protocol test does not establish that arbitrary remote clients or transports are safe.

Check your understanding

Does adopting MCP replace the agent loop or evaluation runner?

Check your reasoning

No. MCP standardizes capability interaction. Your harness still owns planning, state, authorization policy, budgets, and outcome evaluation.
