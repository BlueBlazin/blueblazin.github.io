Finish the Last Four Final Task Fixtures

By the end of this hour

  • Finish sixteen reproducible final-task fixtures.
  • Keep fixture validation separate from agent performance evaluation.

Before you begin

  • The three added fixture-authoring hours have created final-01 through final-12 with reference/no-op controls.
  • Use the host-owned fixture and grader templates; final-13 through final-16 remain reserved and have never been run by an agent.

Environment or workflow question? Day 0 handbook.

The key idea

The first twelve final fixtures were built in three dedicated authoring sessions. This hour completes the last four, then verifies that all sixteen have explicit initial states and outcome contracts. Hold out genuinely different behaviors or task families where possible; a renamed development example provides weak evidence. Fixture validation does not expose agent performance, but you still know the authored tasks, so this remains a small held-out development split. Keep graders protected and use the isolated runner for candidate-code tests.

Hour 2 of 2 · 60 minutes

Verify Reference And Broken Controls

By the end of this hour

  • Check that final graders accept reference solutions.
  • Check that no-op and deliberately broken controls fail.

Before you begin

  • Sixteen final fixtures and their deterministic graders.
  • Reference solutions or fixture-level outcome constructors for those tasks.

Environment or workflow question? Day 0 handbook.

The key idea

A grader is executable measurement code and can be wrong. A reference control asks whether the intended outcome is accepted; a no-op asks whether doing nothing can earn a pass. A deliberately broken control probes a specific requirement that the no-op may not isolate. These checks improve the measurement before any final agent results exist. Passing controls is necessary but does not prove that every possible shortcut is excluded. Record what was tested and keep the grader narrowly tied to the task specification.

  3. Build

    35 min

Add or reuse one deliberately broken control that violates an important requirement, such as a wrong value or omitted edit. Run these controls in a table-driven batch with no agent calls. Repair invalid graders against the written task contract and rerun affected controls. Save expected and observed grades, including every repair made before the freeze.

  4. Verify and save

    10 min

    Commit a control-results table covering all sixteen final tasks and confirm that reference, no-op, and broken expectations hold.

What to save

Final graders accept references and reject controls.

Watch for: Do not weaken task requirements simply to make an inconvenient reference pass.

Check your understanding

Does a reference pass alone establish that a grader is useful?

Check your reasoning

No. A grader that always returns success also accepts the reference. Negative controls test whether it rejects missing or incorrect outcomes.
