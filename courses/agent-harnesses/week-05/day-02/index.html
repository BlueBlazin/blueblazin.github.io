Define The Compacted Context Record

By the end of this hour

  • Define a compact context record with evidence pointers.
  • Predeclare a context ceiling and compaction activation rule.

Before you begin

  • Use saved development traces, the model message contract, and durable run-state fields.

Environment or workflow question? Day 0 handbook.

The key idea

Context compaction replaces part of the model-visible history with a smaller representation, so it is a lossy transformation rather than ordinary storage. The full event log should remain available for inspection even when messages are omitted from the next request. A useful compact record retains the objective, constraints, decisions, evidence pointers, changed files, and pending actions. Separate verified observations from guesses. Define the input ceiling and reserved output space before implementing the policy; otherwise an apparent improvement may simply come from giving one condition more usable context.

Your 60-minute plan

  1. Retrieve

    5 min

    From memory, list the minimum facts a new model turn would need to continue one of your interrupted development tasks.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H18: Compaction and structured notes for long tasks. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Create docs/compaction-policy.md and a CompactedContext schema containing objective, constraints, decisions with support, evidence pointers, changed files, and pending actions. Specify how pointers identify file/range/version or event ids, and how stale evidence is marked. Choose a small explicit model-input ceiling suitable for development and reserve room for the next response separately. Define the activation trigger and maximum summary size. Hand-author one compact record from an existing trace and list facts deliberately dropped. Preserve the full trace outside the model request; no summary call is required today. Define the ceiling over the full provider input, including system instructions and tool schemas, and ensure input plus reserved output fits the selected model’s context limit. If required fixed content alone exceeds the ceiling, fail with a context-budget outcome rather than silently increasing it.

  4. Verify and save

    10 min

    Check the hand-authored record against the original trace. Save the schema, ceiling, activation rule, and one example with at least one resolvable evidence pointer.

What to save

Compaction schema and token budget.

Watch for: A summary that states an unverified model guess as an observed fact can amplify an earlier error.

Check your understanding

Why is compaction a policy decision rather than merely serializing run state?

Check your reasoning

It chooses which information the model sees under a budget and may discard important details. Durable storage can retain everything; compact model context cannot.
