Interrupt And Verify Mutation Handling

By the end of this hour

  • Inject interruptions around a mutating tool action.
  • Prove restart does not silently duplicate edits.

Before you begin

  • Use resume/reconciliation code and a disposable single-file replacement fixture.

Environment or workflow question? Day 0 handbook.

The key idea

Crash tests should target the gaps between durable intent, actual mutation, and durable completion. A normal clean shutdown exercises none of these gaps. Add deterministic fault hooks so tests can stop execution at exact points and then start a new harness instance from saved state. Check observable effects, not only terminal status: count write invocations, compare file contents, and inspect reconciliation events. The goal is a clear demonstration for the supported local mutation contract, with uncertainty handled explicitly rather than hidden by a successful-looking resume.

Your 60-minute plan

  1. Retrieve

    5 min

    Name the two interruption points most likely to reveal duplicate mutation or lost completion records.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Spend 10 minutes on H23: Inject failures at exact function boundaries. Stop at the time limit and use the page as a reference while building.

  3. Build

    35 min

    Add test-only fault hooks immediately before the file mutation and immediately after it but before completion is saved. For each case, start from a fresh fixture, interrupt the first harness instance, then create a new instance using the checkpoint. Assert final file contents, write count, action id continuity, and exactly one terminal outcome. Include the after-mutation case where the restarted harness recognizes the intended contents and performs no new write. Add a conflict variant if time remains, preserving its stopped outcome rather than auto-repairing it. Check that restarting cannot replenish the request/spend allowance or extend the original deadline.

  4. Verify and save

    10 min

    Save tests/test_resume.py results and two readable restart traces. Write a brief guarantee statement restricted to the tested replacement-file contract and its stated storage assumptions.

What to save

Both interruption scenarios pass without duplicate edits.

Watch for: Do not claim universal exactly-once execution from a passing test of one local file-replacement operation.

Check your understanding

Why is a test that calls save_checkpoint and then exits normally insufficient?

Check your reasoning

It avoids the uncertain crash windows. The important failures occur between intent persistence, side effects, and completion persistence, so tests must interrupt those boundaries.
