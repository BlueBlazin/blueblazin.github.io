Implement Grouped Query Attention Heads

By the end of this hour

  • Implement separate query-head and KV-head counts.
  • Match GQA against an explicitly expanded KV reference.

Before you begin

  • A tested RoPE function and multihead attention implementation.
  • A tiny configuration with Hq=4, Hkv=2 and even head dimension.

Environment or workflow question? Day 0 handbook.

The key idea

Grouped-query attention assigns several query heads to one key/value head. Q has Hq heads while K and V have Hkv; this exercise requires Hq divisible by Hkv. It reduces stored K/V state relative to ordinary multihead attention, while the number of query score rows still follows Hq. An expanded reference repeats each KV head for its associated query group. That reference is deliberately simple: matching it establishes the grouping semantics before any inference-memory or speed claim is made.

Resources for this hour

Read the indicated section, not the entire source. The core reading fits inside the plan below. A video is an alternative to reading, not extra homework.

  • Core · 10 min · paper
    GQA: Training Generalized Multi-Query Transformer Models

    Method and attention-group diagram; MHA/GQA/MQA head sharing.

Your 60-minute plan

  1. Retrieve

    5 min

    For Hq=4 and Hkv=2, write which KV head each query head uses. Which tensors have a smaller head-axis size?

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read A3’s GQA description. Write Q, K, V and score shapes for B=2, T=8, Hq=4, Hkv=2 and D=16.

  3. Build

    35 min

    Give the attention module separate query and KV projection output widths. Reshape Q to [B,Hq,T,D] and K/V to [B,Hkv,T,D], applying RoPE to each before grouping. Implement a clear grouped computation or an initial repeat-interleave path. Independently construct a reference by expanding each KV head across its query group, then reuse standard attention. Compare outputs and selected input/projection gradients on a fixed small case. Reject invalid head ratios with a useful error rather than relying on a reshape failure.

  4. Verify and save

    10 min

    Save a head-mapping table and reference comparisons for Hkv=Hq, Hkv=1 and Hq=4/Hkv=2.

What to save

Grouped heads match the expanded-KV reference.

Watch for: Using repeat instead of the intended contiguous repeat-interleave can assign the wrong KV head to a query group.

Check your understanding

Does GQA automatically reduce the size of an explicitly materialized attention-score tensor?

Check your reasoning

No. Scores still have one row group per query head, typically [B,Hq,T,T]. GQA directly reduces K/V projection and cache dimensions; score materialization is a separate issue.
