Run The Bounded Fine Tuning Experiment

By the end of this hour

  • Run a capped LoRA SFT experiment using the frozen training split.
  • Monitor validation behavior and preserve a reproducible adapter checkpoint.

Before you begin

  • Validated prompt masks, graders and held-out baseline.
  • The frozen 300-example train and 50-example validation partitions.

Environment or workflow question? Day 0 handbook.

The key idea

This experiment changes only the low-rank adapter weights while keeping the base model and data protocol fixed. Training loss measures fit to training completions; validation loss or task accuracy helps identify overfitting and choose a checkpoint without consulting final outcomes. A small synthetic dataset can be exhausted quickly, so write down the epoch or step cap before running. The aim is a traceable experiment with a baseline and limits. A larger model, longer run or repeated held-out tuning would change the question and the budget.

Your 60-minute plan

  1. Retrieve

    5 min

    Name the quantities that remain fixed between the baseline and adapted evaluation, and which parameters are allowed to change.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Revisit A5’s frozen-base adaptation setup. Inspect a few training batch lengths to choose a batch/accumulation setting that fits the available device.

  3. Build

    35 min

    Choose and record rank, alpha, learning rate, batch size, accumulation, maximum epochs/steps and a wall-clock cap that fits the remaining build time. Run a tiny memory smoke test on a disposable copy or restore state afterward. Start the actual run from the saved zero-update adapter initialization and a fresh optimizer, then train on the 300 examples with the verified masks. Log completion-token loss and periodic validation metrics on the 50-example split. Use a checkpoint selection rule declared before viewing results, such as lowest validation loss among the scheduled evaluations. Save adapter weights, optimizer state and configuration, including exact base revision and data checksums. Stop at the cap even if the curve is disappointing.

  4. Verify and save

    10 min

    Save train/validation curves, selected checkpoint identity, wall time and any compute cost. Confirm base parameters still match the original values or their checksums.

What to save

Adapter checkpoint and training/validation curve recorded.

Watch for: Do not use the 100 held-out examples for checkpoint selection or learning-rate tuning.

Check your understanding

What should you conclude if training loss falls while validation loss rises?

Check your reasoning

The model is fitting the training examples while generalization to the validation distribution is worsening, consistent with overfitting. Use the predeclared validation-based selection rule and report the behavior rather than consulting held-out results to rescue it.
