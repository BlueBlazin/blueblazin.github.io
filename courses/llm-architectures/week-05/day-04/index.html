Specify Sparse Expert Routing Shapes

By the end of this hour

  • Specify a four-expert, top-2 layer with unambiguous tensor shapes.
  • Calculate total parameters and the parameters used for one token.

Before you begin

  • Your working PyTorch feed-forward block and its parameter count.
  • A tiny CPU FP32 tensor with batch 2, length 3 and model width 16.

Environment or workflow question? Day 0 handbook.

The key idea

A sparse expert layer selects a small subset of feed-forward networks for each token. In this toy design, flatten the batch and sequence into N tokens, compute router logits of shape [N, 4], and choose two experts per row. Normalize the selected logits with a softmax before combining their outputs. All four expert weight sets exist in memory, even though one token uses only two. This distinction separates stored parameters from token-level computation; it does not, by itself, establish faster execution.

Your 60-minute plan

  1. Retrieve

    5 min

    Sketch the input, hidden and output dimensions of your existing feed-forward block without opening its code.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Use A7 to identify routing and the distinction between routed and shared experts. Your required implementation has four routed experts and no shared expert.

  3. Build

    35 min

    Create notes/moe-design.md. Define x:[N,16], router weights [16,4], selected indices [N,2], selected weights [N,2], expert outputs [N,16], and restored output [2,3,16]. Choose a simple two-linear-layer expert with hidden width 32 and no biases. Work out one expert’s parameter count and then the router-plus-four-expert total. Compute the router-plus-two-expert count for one token. State your activation, top-2 normalization, tie behavior and no-token-dropping policy so tomorrow’s forward pass has a precise contract. Label this as a teaching MoE, not a reproduction of DeepSeekMoE.

  4. Verify and save

    10 min

    Check every matrix multiplication by matching its inner dimensions. Save the count calculation and compare it with the shapes you intend to allocate.

What to save

Dimensioned design and parameter accounting recorded.

Watch for: Calling active parameters a memory-footprint estimate hides the weights of unselected experts.

Check your understanding

Does top-2 routing among four experts halve the layer’s stored weight memory?

Check your reasoning

No. All four expert weight sets remain stored; only the subset evaluated for a particular token is reduced.
