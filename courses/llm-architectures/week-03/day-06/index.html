Design And Implement KV Cache

By the end of this hour

  • Represent per-layer KV cache state with explicit lengths and positions.
  • Implement prefill and one-token decode for the PyTorch decoder.

Before you begin

  • The tested modern PyTorch decoder and RoPE offsets.
  • An inference-only path with dropout disabled.

Environment or workflow question? Day 0 handbook.

The key idea

During causal decoding, earlier keys and values need not be recomputed for each new token. A cache stores per-layer K and V, typically [B,Hkv,Tcached,D], while a new query attends to the relevant stored prefix. RoPE makes positions part of the cache contract: a key is rotated for its absolute position once before storage. Prefill processes a prompt; decode extends it. This session uses simple growing tensors for clarity. Preallocated buffers and optimized serving are separate engineering choices, not prerequisites for proving cache correctness.

    5 min

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Review A2/A3 for GQA cache dimensions and rotary positions. Sketch explicit cache inputs and outputs for one decoder layer.

  3. Build

    35 min

    Add an inference method that accepts optional per-layer K/V state and returns logits plus new state. Use model.eval() and torch.inference_mode() around this inference path. Begin with a short full-prompt prefill, then decode exactly one new token at a time. Rotate new keys using positions beginning at the existing cache length or an explicit absolute offset, concatenate along the token axis and preserve Hkv rather than expanding cached heads. Track logical length separately from token content. Print or return a small state-shape trace for a three-token prompt followed by two decode calls; defer speed tuning.

  4. Verify and save

    10 min

    Save the cache-state contract and shape trace. Check that old cached entries remain unchanged and length grows by the number of appended tokens.

What to save

Incremental decoding updates cache shapes and offsets correctly.

Watch for: A generic causal-mask flag can have unexpected alignment when query length is one and key length is longer; make the allowed positions explicit.

Check your understanding

Why should a cached key not be rotated again on every decode call?

Check your reasoning

It already contains the rotation for its original absolute position. Rotating it again changes the represented position and corrupts attention scores.

Hour 2 of 2 · 60 minutes

Verify Cached And Full Prefix Logits

By the end of this hour

  • Compare cached decoding with full-prefix recomputation.
  • Exercise prompt lengths and offsets that expose off-by-one bugs.

Before you begin

  • The explicit cache implementation and shape trace.
  • A deterministic evaluation configuration with fixed weights.

Environment or workflow question? Day 0 handbook.

The key idea

Cache correctness is a numerical equivalence claim, not a comparison of sampled text. For the same token prefix, the last-position logits from full recomputation should match those from prefill followed by incremental updates. Position indices and allowed-key masks must use the same convention in both paths. Testing only one prompt at offset zero can hide indexing errors. Vary the prompt length, append several known tokens and repeat with a nonzero absolute offset while keeping the underlying tokens and parameters fixed.

Your 60-minute plan

  1. Retrieve

    5 min

    For a prefix of length T, state which full-forward logits should match the next cached decode output after appending one known token.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Review your A3-derived rotary identity and cache contract. Make a table of prompt length, appended length and absolute offset cases.

  3. Build

    35 min

    Construct fixed token sequences long enough for several decode steps. Test prompt lengths such as 1, 3 and 7, then append two or three known tokens without sampling. At each step, run the uncached decoder on the identical full prefix and compare its final-position logits with the cached result. Repeat with absolute positions starting at a nonzero offset such as 11. Include the prefill-only comparison and inspect the first failing position if needed. Keep any sliding-window or cache-eviction behavior out of this test because it changes the reference.

  4. Verify and save

    10 min

    Save per-case maximum errors and assert the agreed tolerances. Record the exact causal-mask convention used for single-token decode.

What to save

Cache and full-prefix logits agree within stated tolerances.

Watch for: Comparing a cached result after appending a token with a full-prefix result before appending it creates a one-step alignment error.

Check your understanding

Why is matching greedy-generated text an insufficient cache test?

Check your reasoning

Different logit vectors can still select the same argmax token for several steps. Direct logit comparisons detect smaller and more localized correctness errors.
