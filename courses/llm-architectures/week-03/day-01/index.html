Verify Cross Framework Primitive Gradients

By the end of this hour

  • Compare selected primitive parameter and input gradients.
  • Diagnose numerical mismatches without blindly widening tolerances.

Before you begin

  • The shared NumPy parameter bundle and forward-parity table.
  • Working autograd/grad examples in both frameworks.

Environment or workflow question? Day 0 handbook.

The key idea

Matching forward outputs does not guarantee matching derivatives: a detached value, wrong broadcasting reduction or custom gradient path can preserve a result while changing learning. For each primitive, differentiate the same scalar objective in both frameworks. A weighted sum of outputs uses a fixed upstream gradient and avoids comparing two differently reduced losses. Compare both input gradients and a representative parameter gradient. When errors appear, inspect dtype, epsilon, layout and the first divergent operation before changing any threshold; a tolerance should describe expected arithmetic, not hide a bug.

Your 60-minute plan

  1. Retrieve

    5 min

    Give one example of a computation with unchanged forward values but broken gradients, such as detaching an intermediate.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read A4’s autodiff guidance on scalar objectives and gradient pytrees. Choose a fixed output-weight tensor for your scalar objective.

  3. Build

    35 min

    For projection, RMSNorm, RoPE and SwiGLU, define the scalar sum(output * fixed_probe) using identical probe arrays. Compute gradients with respect to input and selected parameters in both frameworks, translating weight layouts before comparison. If a discrepancy needs diagnosis, add a centered FP64 finite-difference check for one scalar parameter. Use NumPy/PyTorch float64, or enable jax_enable_x64 before creating arrays in a separate JAX diagnostic process; confirm the actual dtype and keep the normal parity suite FP32. Extend the parity table with maximum errors and tolerances. Include a nonzero rotary offset and a nonuniform normalization input so identity-like special cases do not make a broken derivative look correct.

  4. Verify and save

    10 min

    Run the complete primitive suite from a clean process and save the comparison table plus any resolved mismatch and its cause.

What to save

PyTorch and JAX primitive output and gradient parity table.

Watch for: Do not accept a larger tolerance until you have ruled out layout, reduction, epsilon and dtype mismatches.

Check your understanding

Why can comparing only the gradient of sum(output) miss a bug?

Check your reasoning

A uniform upstream gradient can cancel or hide certain permutations and reduction errors. A fixed nonuniform probe exercises a richer derivative direction while keeping the objective scalar.
