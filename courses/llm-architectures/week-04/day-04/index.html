Check Initialization And Merge Behavior

By the end of this hour

  • Verify that adapter initialization preserves the base function.
  • Implement merge behavior without applying the update twice.

Before you begin

  • The small tested LoRA wrapper.
  • A fixed input batch and a copy of the original base weights.

Environment or workflow question? Day 0 handbook.

The key idea

Initializing one low-rank factor to zero makes BA zero, so the adapter initially reproduces the base layer exactly. A common choice is random A and zero B. At that instant B can receive a gradient, while A’s gradient is zero because it is multiplied through B; after B changes, A can learn as well. For inference, merging adds the scaled BA into W. A merged layer must stop applying the separate adapter branch or it will count the same update twice.

Resources for this hour

Read the indicated section, not the entire source. The core reading fits inside the plan below. A video is an alternative to reading, not extra homework.

Your 60-minute plan

  1. Retrieve

    5 min

    If B=0 and A is nonzero, which factor can receive a nonzero gradient on the first step, and why?

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read A5’s initialization and merge discussion. Write the merged weight equation and the state transition your wrapper will use.

  3. Build

    35 min

    Initialize random A and zero B, then compare wrapper and base outputs on the same inputs. Inspect first-step gradients to confirm the expected asymmetry. Apply one small optimizer update so BA becomes nonzero. Implement a merge operation on a copy for inference, adding (α/r)BA to the base and disabling the adapter branch. Compare merged and unmerged outputs across two input batches. Make repeated merge calls either an explicit error or a no-op, and preserve the unmerged checkpoint rather than overwriting your only training copy.

  4. Verify and save

    10 min

    Save zero-update, first-gradient and merged-output checks with FP32 tolerances. Confirm a second merge cannot silently double the update.

What to save

Initialization preserves the base; merged and unmerged outputs agree.

Watch for: After merging BA into W, leaving the adapter branch active applies the update twice.

Check your understanding

Why does initializing both A and B to zero prevent this ordinary two-factor adapter from learning initially?

Check your reasoning

Each factor’s gradient is multiplied through the other factor. With both factors zero, both gradients vanish for the low-rank branch, so the adapter remains zero under ordinary gradient updates.
