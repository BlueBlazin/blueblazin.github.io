Freeze Data And Run Training Pilots

By the end of this hour

  • Freeze a document-level split and shared token stream.
  • Run short, capped pilots in both frameworks on the same workload.

Before you begin

  • Both framework training loops and the CPU parity report.
  • The course compute guide, remaining budget and a small licensed dataset subset.

Environment or workflow question? Day 0 handbook.

The key idea

A training pilot estimates whether the intended workload fits the time and memory budget. It is not the main experiment. Data must be split by document before chunking so related fragments do not leak across train and validation. Both frameworks should consume the same packed or separate examples, tokenizer and target convention. Hardware may differ between local backends, so record it and avoid turning those observations into a framework speed ranking. A small measured pilot is more informative than a guessed overnight allocation.

Your 60-minute plan

  1. Retrieve

    5 min

    Explain how splitting overlapping token chunks after tokenization can leak one document into both train and validation.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read A12’s dataset information and the course architecture data standard. Review A4’s blocking requirement for asynchronous timing.

  3. Build

    35 min

    Select and pin a modest TinyStories subset, recording source revision and license information. Assign document IDs to train and validation before tokenization, preserve EOS boundaries and use separate examples or an explicit boundary mask. Save one shared token stream and a small batch manifest for both frameworks. Choose a candidate model size from the course range only if its measured memory fits, otherwise reduce it. Run bounded pilots of at most five minutes per framework after a tiny smoke check, saving configuration, token counts, loss samples and hardware/backend identity.

  4. Verify and save

    10 min

    Save the split manifest, tokenizer identity, pilot logs and actual compute charge if applicable. Stop any rented GPU when the bounded work finishes.

What to save

Both frameworks complete short pilots using the frozen split.

Watch for: Do not launch the long run before inspecting pilot memory, throughput and validation behavior.

Check your understanding

Can a faster MPS PyTorch pilot than a CPU JAX pilot establish that PyTorch is faster?

Check your reasoning

No. Backend and hardware differ, so the observation estimates those particular setups. A framework comparison would need matched hardware, precision, shapes and measurement conditions.
