Overfit And Sample Tiny Sequences

By the end of this hour

  • Overfit one tiny repeated batch as a correctness check.
  • Implement autoregressive generation with explicit decoding settings.

Before you begin

  • A verified training step and the fixed tiny batch.
  • A writable results directory for loss values and samples.

Environment or workflow question? Day 0 handbook.

The key idea

Overfitting one repeated batch removes data diversity as a confound: the network should learn the particular next-token mapping when it has sufficient capacity. This is an engineering check, not evidence of generalization. Autoregressive generation repeatedly selects a token from the final position’s logits and appends it to the prefix. Greedy decoding is useful for deterministic inspection, while sampling introduces extra random choices. A smooth loss curve and plausible text can reveal different failures, so save both and report precisely what data the model has seen.

What to save

Tiny-batch loss meets its documented target; samples and curve saved.

Watch for: Do not label memorized training text as a general language-model capability.

Check your understanding

Why are generated samples weaker evidence of correctness than the causal and loss tests?

Check your reasoning

A model can emit plausible fragments despite a mask or target-alignment bug. Numerical and invariance tests check specific properties that a few subjective samples cannot establish.

Save And Resume Model Training

By the end of this hour

  • Save all state needed to continue the same training run.
  • Compare a resumed path with an uninterrupted reference.

Before you begin

  • The tiny training loop and generation checks.
  • A supported deterministic CPU configuration for the comparison.

Environment or workflow question? Day 0 handbook.

The key idea

A checkpoint is a snapshot of a state machine. Model weights are only one part: AdamW moments, scheduler position, random generators and the data cursor all influence the next update. Saving just weights can reproduce inference logits while failing to reproduce training. First verify exact or tightly matched evaluation logits after reloading. Then compare two training branches that begin from identical state: uninterrupted updates and a save/reload interruption. Restrict the comparison to a setup with supported deterministic behavior and document any numerical tolerance you need.

Your 60-minute plan

  1. Retrieve

    5 min

    Name five state items beyond model weights that may affect the next training step.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Use A13’s checkpoint handling as a reference for optimizer and iteration state. Decide how your fixed data cursor and random generators will be serialized.

  3. Build

    35 min

    Extend your checkpoint with model configuration, weights, optimizer state, scheduler state if present, step number, Python/NumPy/framework RNG states and data position. Include the tokenizer and sample manifest identity. Build a short CPU experiment: initialize once, save the initial state, run several steps uninterrupted, then repeat from that state with a checkpoint/reload in the middle. Before resuming, compare evaluation logits on the fixed batch. After resuming, compare the loss sequence and selected parameters at every remaining step.

  4. Verify and save

    10 min

    Save a resume comparison table and a short explanation of the supported deterministic setting. Record framework version and any backend-specific limitations.

What to save

Reload reproduces logits; supported deterministic resume reproduces the training trajectory.

Watch for: Restoring RNG state before rebuilding randomly initialized objects can consume it again and shift the resumed sequence.

Check your understanding

Why can identical reload logits coexist with a different next training update?

Check your reasoning

Logits depend on model parameters and inputs, while the next update also depends on optimizer moments, random choices, scheduler position and which batch is consumed next.
