Environment or workflow question? Day 0 handbook.

The key idea

AdamW maintains first and second moments of gradients, applies bias correction, and decouples weight decay from the loss gradient. For the first update from zero moments, m^=g\hat m=gm^=g and v^=g2\hat v=g^2v^=g2, so the adaptive term is g/(∣g∣+ε)g/(|g|+\varepsilon)g/(∣g∣+ε). The decay term scales the old parameter separately. A training step must clear stale gradients, compute the loss, backpropagate, clip if needed and update parameters. Clipping changes the gradient fed to the optimizer; record the unclipped norm to distinguish a stable step from a frequently clipped one.

Your 60-minute plan

  1. Retrieve

    5 min

    Write the derivative of a scalar quadratic and list the correct order of zero_grad, forward, backward, clipping and optimizer.step.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Review AdamW usage in A13. Calculate one step with w=1, g=0.5, learning rate 0.1, weight decay 0.01 and a small explicit epsilon.

  3. Build

    35 min

    Use a scalar torch Parameter to compare built-in AdamW’s first update with this scalar update:

    Set gradient explicitly so the comparison isolates optimizer arithmetic. Then add AdamW to your decoder loop: clear gradients, compute loss, call backward, record total gradient norm, clip to a declared threshold and step. Run a handful of repeated-batch updates, checking finite parameters and loss. Keep learning rate and batch fixed so an implementation error is not hidden by repeated retuning.

  4. Verify and save

    10 min

    Save the scalar comparison and a short step log with loss, gradient norm and learning rate. Confirm a parameter changes and gradients do not accumulate unintentionally.

What to save

Hand calculation agrees with AdamW; training step reduces tiny-batch loss.

Watch for: Do not compare Adam and AdamW with weight decay enabled as though their update rules were identical.

Check your understanding

How would accidentally accumulating gradients change the second training step?

Check your reasoning

The second backward pass would add to the previous gradient. The optimizer would receive a sum rather than the intended current-batch gradient, changing moments and the update.
