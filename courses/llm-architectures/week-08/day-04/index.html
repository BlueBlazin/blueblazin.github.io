Run The Matched Training Ablation

By the end of this hour

  • Run the ablation on the same token stream and budget.
  • Collect measurements directly comparable with the baseline.

Before you begin

  • The completed baseline logs and its final comparable token budget.
  • The frozen ablation configuration and identical data-order seed.

Environment or workflow question? Day 0 handbook.

The key idea

Matched conditions make differences easier to interpret, but one run per setting still leaves substantial uncertainty. Start the ablation from the planned initial state, not from the trained baseline, unless continuation was explicitly the experimental question. Preserve data ordering, validation examples and generation prompts. Record the actual token count at the endpoint so a partial run cannot masquerade as a full-budget result. This session completes one comparison; extra seeds and broader searches remain future work unless the existing budget and course schedule explicitly allow them.

Your 60-minute plan

  1. Retrieve

    5 min

    Identify which initialization the ablation should use and explain why the trained baseline checkpoint is usually the wrong starting point.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Compare the ablation and baseline configuration files, then inspect their first batch identifiers or data-order hashes.

  3. Build

    35 min

    Launch the ablation with the same hard limits, data sequence and final token target used for the baseline. Verify the intended changed setting is active, and check that the first logged token counts and batch identifiers match. Collect training/validation losses at the same cadence and save the same fixed-prompt generations with identical decoding settings. Record checkpoint state and actual runtime. If either arm stops short, preserve the raw endpoints and choose a shared token point for comparison; do not conceal the shorter run through a relabeled plot axis or an extra unplanned training extension.

  4. Verify and save

    10 min

    Save the ablation checkpoint, logs and samples. Check both arms expose a common token interval and add the actual GPU cost to the ledger.

What to save

Ablation results retain matched data order and token budget.

Watch for: Identical random seeds alone do not prove identical data order if preprocessing, packing or resume position differs.

Check your understanding

Why should the ablation normally start from the same initialization policy rather than the final baseline weights?

Check your reasoning

Starting from trained baseline weights changes the experiment into a continuation or adaptation study, confounding the original comparison.
