Build a Controlled Training Experiment

By the end of this hour

  • Freeze one bounded training ablation.
  • Choose a token budget supported by your pilot and remaining compute allowance.

Before you begin

  • Your pilot-sized model configuration, frozen tokenizer/data split and earlier throughput pilot; use 30–60M parameters only if the measured time and memory allow it.
  • The current compute ledger and checkpoint/resume support.

Environment or workflow question? Day 0 handbook.

The key idea

An ablation asks what changes when one declared choice changes under controlled conditions. Token count and data order matter because a model trained on more or easier data is not a clean comparison. A small budget is acceptable if the claim stays small. Choose the allowance from measured throughput, not an aspirational parameter-count label. Training may consume cloud wall time beyond active study time, but the launcher must enforce a token or time cap and save state so your daily work remains bounded.

Your 60-minute plan

  1. Retrieve

    5 min

    List the controls needed to compare two learning curves: initialization policy, data order, token budget, validation data and logging cadence.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Review A1’s experiment discipline and A12’s dataset characteristics. Check the data revision and split used by your current training pipeline.

  3. Build

    35 min

    Create the baseline and ablation configuration files plus a runnable launcher using your existing training entry point. Change only AdamW weight decay and output paths; keep architecture, initialization, tokenization, data order and validation cadence fixed. Make token/time stopping conditions executable and verify them with a tiny two-step smoke run. Restore the common initial state afterward. Calculate a shared token budget from the measured pilot using the Day0 template, including both arms and overhead. Save the two launch commands and confirm a configuration diff contains only the intended experimental difference.

  4. Verify and save

    10 min

    Diff the configurations and confirm only the declared ablation choice and output paths differ. Save the planned budget, estimated cost and resume commands.

What to save

Baseline and ablation differ in one declared choice.

Watch for: Changing normalization, optimizer and schedule together prevents attributing an observed difference to one choice.

Check your understanding

Why match consumed tokens rather than only training steps?

Check your reasoning

Batch sizes, accumulation or sequence packing can change how much training data a step represents.
