Compare MLA And GQA Memory

By the end of this hour

  • Derive architecture-specific cache byte formulas.
  • Calculate and check a concrete MLA-versus-GQA example.

Before you begin

  • The persistent-cache inventory in notes/mla.md.
  • Your GQA cache formula from the earlier KV-cache activity.

Environment or workflow question? Day 0 handbook.

The key idea

Memory accounting is easiest when you count elements first and multiply by bytes per element last. For a simple compact MLA cache, count one latent width plus one retained positional-key width per token per layer. For GQA, count both key and value heads. Choose an illustrative configuration and label it as such; matching a few dimensions does not make two models quality-equivalent. Separate bytes from MiB, and distinguish logical tensor storage from allocator overhead, workspace memory and the weights needed to execute inference.

Your 60-minute plan

  1. Retrieve

    5 min

    Write the GQA element count from memory: 2 times batch, layers, tokens, KV heads and head width.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Use A8’s cache comparison to check which MLA widths are retained in your chosen inference representation.

  3. Build

    35 min

    In notes/mla.md, use an illustrative B=1, L=8, T=2048, FP16 configuration. Set GQA KV heads=4 and head width=64; set the compact MLA latent width=128 and positional-key width=32. Calculate the logical cache sizes, with s=2s=2s=2 bytes per element:

    MGQA=2BLThkvds,MMLA=BLT(r+dpos)s.\begin{aligned} M_{\mathrm{GQA}} &= 2BLT h_{\mathrm{kv}}d s,\\ M_{\mathrm{MLA}} &= BLT(r+d_{\mathrm{pos}})s. \end{aligned}MGQA​MMLA​​=2BLThkv​ds,=BLT(r+dpos​)s.​

    Convert both results to MiB using 2202^{20}220, calculate their ratio, then double T and predict the new values. Verify arithmetic in a ten-line script or calculator. State that projection weights and temporary tensors are excluded.

  4. Verify and save

    10 min

    Check the example gives 16 MiB for GQA and 5 MiB for the specified compact MLA cache. Save equations, units and the assumptions needed for those numbers.

What to save

Worked cache-memory comparison with explicit configuration and units.

Watch for: The MLA formula depends on the actual retained representation; do not apply it to every implementation labeled MLA.

Check your understanding

Why does a lower cache-byte count not guarantee a proportionally faster decoder?

Check your reasoning

Runtime also depends on computation, memory access, kernel implementation, batching and hardware; logical cache size is only one factor.
