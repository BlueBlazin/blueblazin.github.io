Survey Post Training And Multimodal Interfaces

By the end of this hour

Before you begin

  • Your structured-task SFT experiment and prompt/response masking code.

Environment or workflow question? Day 0 handbook.

The key idea

A useful post-training survey starts with the data and feedback available to the optimizer. SFT learns from target responses. Preference-based methods use information about which responses are preferred, while reward-based policy optimization uses scores on sampled outputs. These categories do not imply that every objective uses the same model copies or sampling process. Multimodal interfaces add a different question: how image or other non-text representations become inputs the language model can consume. Today’s goal is a precise interface and objective comparison, not another training run.

Your 60-minute plan

  1. Retrieve

    5 min

    Recall which tokens received loss in your SFT task and what information the training example supplied.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read the selected DPO and DeepSeekMath/GRPO objective descriptions, then the chosen Gemma multimodal input/interface material. Use the 3+4+3-minute allocation on the resource cards; inspect inputs and data flow rather than reading full papers.

  3. Build

    35 min

    Add a survey table to notes/current-architectures.md with rows SFT, DPO and GRPO, and columns training example or sampled group, feedback signal, reference/baseline role as described by the source, and what your current trainer lacks. Write one concrete example for each using your earlier structured-output task. Then draw a four-stage multimodal interface: non-text input, encoder/features, adapter or projection, and language-model input stream. Label which parts your text-only code already has and which are absent. Explicitly mark this whole session survey-only; no reward pipeline or vision encoder implementation is required.

  4. Verify and save

    10 min

    Check that preferred/rejected pairs are not conflated with rewarded sampled groups. Save the table and one unresolved conceptual question for later review.

What to save

Concise survey distinguishes objectives and interface changes.

Watch for: A JSON tool-call format is still text output; producing it does not by itself make a model multimodal.

Check your understanding

Why is replacing an SFT loss function alone insufficient to create a complete reward-based training pipeline?

Check your reasoning

The pipeline also needs sampled outputs, feedback or rewards, the method’s baselines/reference handling, and controlled optimization and evaluation.
