Validate Attention And Cache Accounting

By the end of this hour

  • Validate each attention configuration against the appropriate reference.
  • Match actual cache tensor storage to the theoretical byte count.

Before you begin

  • The frozen MHA/GQA configurations and protocol.
  • Your full-prefix versus cached-logit tests and expanded-KV reference.

Environment or workflow question? Day 0 handbook.

The key idea

Correctness comparisons must respect what is supposed to be equal. Each configuration’s cached logits should agree with its own full-prefix logits, and GQA should agree with an expanded-KV reference using the same grouped weights. Independently parameterized MHA and GQA models need not emit matching logits. For storage, count the tensors actually retained by the cache rather than a hypothetical minimum. An implementation that expands and stores grouped keys may have correct output yet fail to realize the intended cache reduction.

Your 60-minute plan

  1. Retrieve

    5 min

    State two valid equality checks and one invalid cross-model equality assumption for today’s study.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read the existing cache tests and A3’s grouping definition. Confirm the expansion reference repeats each KV head into the correct query-head group.

  3. Build

    35 min

    Run full-prefix versus incremental-cache checks for both configurations at each supported test length, using fixed tokens and evaluation mode. Run the grouped attention against the expanded-KV reference separately. For each prompt length, calculate 2*B*L*T*h_kv*d_head*bytes_per_element and compare it with the sum of numel times element_size over the actual retained K/V tensors. Save a CSV with configuration, length, expected bytes, observed tensor bytes, maximum logit error and tolerance. If the cache preallocates capacity, report logical used bytes and allocated capacity separately.

  4. Verify and save

    10 min

    Require the correctness gates to pass before timing. Save the test output and storage table, including any declared cache-capacity policy.

What to save

Correctness gates pass and cache-byte calculations are recorded.

Watch for: Counting only used positions while labeling the result allocated GPU memory hides preallocated cache capacity.

Check your understanding

Can two independently initialized MHA and GQA models be expected to have equal logits?

Check your reasoning

No. Their weights and K/V parameterizations differ; compare each implementation to a mathematically equivalent reference.

Measure Prefill And Decode Separately

By the end of this hour

  • Measure prefill and cached decode as separate workloads.
  • Save synchronized raw samples and exact device conditions.

Before you begin

  • Passing correctness gates and the frozen protocol.
  • A short NVIDIA GPU session or an explicitly separate local device run.

Environment or workflow question? Day 0 handbook.

The key idea

Prefill processes the prompt and creates state; cached decode generates subsequent tokens while reading that state. They have different shapes and bottlenecks, so a single end-to-end time hides useful information. GPU work is asynchronous: a host timer must use synchronization or device events correctly. Keep setup, compilation and warm-up outside steady-state samples. During decode, context grows, so compare the same starting prompt length and number of generated steps for both variants. Report the workload measured instead of implying a universal speed ranking.

Resources for this hour

Read the indicated section, not the entire source. The core reading fits inside the plan below. A video is an alternative to reading, not extra homework.

  • Core · 10 min · tutorial

Your 60-minute plan

  1. Retrieve

    5 min

    Explain why timing a function return without synchronization can underestimate GPU execution time.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Reopen your frozen protocol and benchmark helper; identify exactly where warm-up and synchronization occur.

  3. Build

    35 min

    On the selected device, load the two frozen configurations and use the same fixed token batches. Use evaluation mode plus torch.inference_mode() throughout the benchmark. Warm up each measured path. Record repeated prefill samples for every chosen prompt length, then cached-decode samples using the same starting context and fixed number of decode steps. Rebuild or reset the cache between independent trials so earlier trials do not extend later contexts. Save every timing sample, hardware name, software versions, precision and cache policy to experiments/gqa-vs-mha/raw.csv plus a metadata file. Stop at the predefined sample count; this session does not include tuning either implementation.

  4. Verify and save

    10 min

    Inspect one sample group for obvious setup/compilation contamination. Save medians and spread alongside raw samples, then shut down paid compute when the measurements are complete.

What to save

Raw prefill/decode timings and hardware settings saved.

Watch for: Do not pool MPS and NVIDIA timings into one median; keep device results separately labeled.

Check your understanding

Why must a decode benchmark reset its cache between independent trials?

Check your reasoning

Otherwise later trials may read longer contexts or start from a different state, changing the workload being compared.
