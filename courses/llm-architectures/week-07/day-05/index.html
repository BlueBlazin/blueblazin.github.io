Hour 1 of 1 · 60 minutes

Specify A Matched Attention Comparison

By the end of this hour

  • Freeze a fair inference protocol for MHA and GQA.
  • State which dimensions match and which projection parameter counts differ.

Before you begin

  • Your validated cached PyTorch decoder.
  • The parameter-count helper and the GQA expanded-KV reference.

Environment or workflow question? Day 0 handbook.

The key idea

A matched inference study holds the task shape and measurement conditions fixed while naming unavoidable architectural differences. Keep model width, query-head count, head dimension, layer count, batch size and precision fixed; vary the KV-head count. K/V projection widths and their parameter counts then change, so this is not a same-parameter model comparison. It is also not a quality-equivalence test. Freezing the protocol before measuring prevents you from choosing only shapes that make one attention variant look favorable.

Resources for this hour

Read the indicated section, not the entire source. The core reading fits inside the plan below. A video is an alternative to reading, not extra homework.

  • Core · 4 min · paper
    GQA: Training Generalized Multi-Query Transformer Models

    Grouped head count and changed K/V projection dimensions.

  • Core · 6 min · tutorial
    PyTorch benchmark tutorial

    Benchmark scope, warm-up and synchronization before coding the paired timing helper.

Your 60-minute plan

  1. Retrieve

    5 min

    Derive the K-projection width for eight query heads with either eight or two KV heads and head width 16.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Review A3’s query-to-KV grouping and the difference between attention structure and a trained model’s quality.

  3. Build

    35 min

    Create experiments/gqa-vs-mha/config.json and a short protocol note. Use your validated decoder dimensions, or a tiny width-128, eight-query-head fixture; compare eight versus two KV heads. Hold layers, batch, token inputs, query/output/MLP dimensions, dtype and device fixed. Select three supported prompt lengths, such as 32,128,512, with a fixed short decode length. Calculate both models’ parameter counts and explicitly identify K/V projection differences. Specify warm-up, synchronized timing, sample count and output columns. Set both models to evaluation mode and use torch.inference_mode() around all timed forward and cache operations. Write a small timing helper using time.perf_counter. For CUDA synchronize immediately before starting and immediately after the measured call; for MPS use its corresponding synchronize call; CPU execution needs no device synchronization. Allocate inputs before timing, run three warm-up calls and choose five measured repetitions. Keep this helper specific to your inference experiment, with no tuning search.

  4. Verify and save

    10 min

    Save the two configurations and expected cache formulas. Check both are valid for the same query-head count and that every difference appears in the protocol.

What to save

Comparison configuration explicitly states shared settings and parameter differences.

Watch for: Sharing query-head count is not the same as matching total parameter count or learned quality.

Check your understanding

Why can you not simply say all weight dimensions are identical in this MHA-versus-GQA comparison?

Check your reasoning

Changing the KV-head count changes the K/V projection output widths unless extra unused or redundant parameters are introduced.
