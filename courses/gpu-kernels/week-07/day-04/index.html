Freeze End To End Decoder Measurements

By the end of this hour

  • Freeze a bounded whole-decoder experiment matrix.
  • Define comparable prefill and decode timing boundaries.

Before you begin

  • The parity-checked supplied decoder fixture with its reference/custom normalization switch.
  • The deterministic random state dict, supplied KV-cache path and cache-parity smoke, and your timing utility. No trained checkpoint is needed.

Environment or workflow question? Day 0 handbook.

The key idea

Prefill processes the prompt and builds state; cached decode generates subsequent tokens using that state. Their workloads and bottlenecks differ, so one aggregate number can conceal useful effects. Eager and compiled execution also differ in fusion and setup costs. Freeze these dimensions before measuring to avoid choosing only favorable cases afterward. A small factorial matrix is sufficient: two execution modes, two kernel settings, and a few supported lengths on one device. Explicitly distinguish model-only device latency from transfer-inclusive wall time, and hold weights, precision, inputs, and output work constant.

Your 60-minute plan

  1. Retrieve

    5 min

    Explain what work occurs during prefill and what remains during one cached decode step.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Revisit K2 timing principles and K5 compiler interaction; identify which conditions might change kernel fusion. Consult the official torch.compile API for dynamic shapes, graph breaks, and recompilation: https://docs.pytorch.org/docs/stable/generated/torch.compile.html.

  3. Build

    35 min

    Create a machine-readable experiment manifest with eager/compiled mode, reference/custom kernel, two or three supported prompt lengths, batch size, dtype, device, fixture code revision and state-dict hash, warmup count, and timing repetitions. Run the supplied full-versus-cached logit parity smoke before timing. Define prefill as prompt processing through the selected output boundary and decode as a fixed number of generated steps with equivalent cache initialization. Add separate fields for transfers, compilation/first-call cost, and warmed device execution. Run only a tiny parity smoke across the four mode/kernel combinations today. Estimate the upcoming GPU time and fit it inside the existing allowance before launching measurements. Fix model.eval() and torch.inference_mode() for every prefill/decode path, including warm-up; eval mode alone does not disable autograd. Ensure prompt length plus generated steps is at most config.max_seq_len (256 by default). For compiled decode, warm the complete fixed decode trajectory, then inspect TORCH_LOGS=recompiles,graph_breaks output outside timing to identify shape recompilation or eager fallback. Freeze the dynamic-shape policy and label graph breaks or fallback instead of treating a completed call as proof of compiled execution.

  4. Verify and save

    10 min

    Save the frozen manifest, timing definitions, parity smoke results, and an estimated rental duration. Avoid starting a full run in this planning hour.

What to save

Frozen experiment matrix and equivalent model configurations.

Watch for: Comparing a compiled custom path with an eager reference and attributing the entire difference to the kernel.

Check your understanding

Why should prefill and decode be separate measurements?

Check your reasoning

Their available parallelism, cache traffic, and sequence-dependent work differ, so a kernel change can help one and hurt the other.
