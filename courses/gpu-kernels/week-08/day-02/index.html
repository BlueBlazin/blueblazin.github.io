Reproduce the Main Kernel Result

By the end of this hour

  • Reproduce the main result from the repaired clean environment.
  • Explain material differences without tuning away unfavorable outcomes.

Before you begin

  • Follow Day0’s clean-environment reproduction recipe using your now-completed benchmark, then confirm the custom-kernel smoke. If reconstruction fails, use the shared repair checklist before this measurement.
  • The frozen main benchmark command and original raw results.

Environment or workflow question? Day 0 handbook.

The key idea

A reproduction need not produce identical milliseconds to be useful, but it should recover correctness and a comparable performance story under disclosed conditions. Hardware clocks, machine sharing, drivers, and package versions can change timings. Compare absolute values, ratios, and variability together rather than insisting on one rounded headline. A large unexplained difference is a result to investigate or report, not a reason to keep rerunning until the best sample matches. The optional tooling note belongs alongside this evidence as a separate reading-based exploration, not as a replacement benchmark.

Your 60-minute plan

  1. Retrieve

    5 min

    State the original main result and the measured variability that accompanied it.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Review K2 sources of timing variation and the exact differences between original and clean manifests.

  3. Build

    35 min

    From the clean compatible environment prepared with the Day0 recipe, run the frozen main benchmark on one representative supported shape and one recorded regression or boundary case. Confirm the actual custom path and numerical correctness, then collect the planned repeated batches. Keep workloads, baselines and precision unchanged. Compare absolute latency, ratios and spread with the original data. Attribute differences only where supported; preserve an unexplained difference. Do not tune performance code to recover a headline. Save the raw original/reproduction pair and a short mechanism note. Report packaging and optional-tooling summaries are in the shared course guide.

  4. Verify and save

    10 min

    Save the reproduction result with both environment identifiers and any unresolved discrepancy. Export artifacts and close the rental session.

What to save

Repeatable benchmark plus current-tooling note and disclosed environment differences.

Watch for: Publishing only the fastest clean-environment batch because it matches the original headline.
