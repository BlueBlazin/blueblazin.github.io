Validate Attention Causality and Tails

By the end of this hour

  • Validate restricted attention tails and causal information flow.
  • Handle padded and fully masked lanes without producing NaNs.

Before you begin

  • A correct exact-tile attention-forward kernel.
  • The frozen support contract, dense reference, and future-perturbation test.

Environment or workflow question? Day 0 handbook.

The key idea

Attention has several interacting masks. Query tails suppress invalid output rows; key tails exclude invalid scores; causality excludes future keys for each valid query. A valid query can encounter a tile with no allowed keys, so its online state must remain unchanged without evaluating undefined negative-infinity differences. Invalid query rows may also produce meaningless intermediate values unless they are handled deliberately, even though their stores are masked. Test the actual supported input dtype and distinguish expected rounding from systematic causal leakage. A smaller validated contract is more useful than claiming support for cases that still produce NaNs.

Your 60-minute plan

  1. Retrieve

    5 min

    List the masks for padded queries, padded keys, and future keys. Explain what should happen to state for a fully masked score row in one tile.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Review K3’s forward attention mask handling and K4’s causal recurrence. Trace one sequence length just above your query block size.

  3. Build

    35 min

    Add the planned key and query tail masks and safe fully masked-row logic. Run lengths 1, one below a tile boundary, exactly at it, one above it, and a larger supported length. Compare outputs with the controlled reference, asserting finite results and recording errors. Reuse the future-K/V perturbation check to catch diagonal causal leakage. Include repeated values and a moderate range of finite inputs within the numerical contract. If a case remains unresolved, narrow and document support explicitly while keeping at least one nonmultiple tail case as the required goal.

  4. Verify and save

    10 min

    Save the updated support/error matrix and the causal perturbation result. Re-run the original exact-tile case after each masking repair.

What to save

Causal and tail tests pass without NaNs on declared inputs.

Watch for: Do not hide unresolved tail failures by advertising only power-of-two lengths; record the blocker and use flex time if needed.

Check your understanding

Why can masked output stores alone fail to prevent NaNs in valid outputs?

Check your reasoning

Invalid key scores or undefined online-state rescaling can contaminate a valid query’s reductions before the final store mask is applied.
