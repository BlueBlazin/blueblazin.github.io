Environment or workflow question? Day 0 handbook.

The key idea

The dx formula requires two row reductions: mean(x²) and mean(g ⊙ w ⊙ x). A simple first kernel assigns one program to a row, loads masked feature lanes, accumulates reductions in FP32, and casts only the final result to the declared output dtype. Invalid lanes must contribute zero, while normalization divides by the true width D rather than the padded block width. Recomputing r is acceptable for this restricted exercise; later profiling can compare recomputation with saving statistics. Correct supported inputs matter before backward-kernel speed.

Your 60-minute plan

  1. Retrieve

    5 min

    From memory, label the two scalar row reductions needed by dx.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Inspect K3 masked loads and normalization reductions; map each reduction to your derived equation.

  3. Build

    35 min

    Add a separate dx kernel to your normalization module, initially supporting contiguous two-dimensional inputs and one declared dtype. Use the existing forward launch convention, a padded feature block, and masks on x, g, w, and the output. Compute both reductions in FP32 and divide by the actual feature count. Start with two rows and a power-of-two width already supported by forward. Supply a fixed upstream g, compare to the tensor reference, and then try one supported non-power-of-two width. Keep the wrapper explicit about unsupported layouts.

  4. Verify and save

    10 min

    Save kernel source and dx error rows for the two widths. Record hardware, dtype, epsilon, and accumulation dtype; end the GPU session after checks.

What to save
