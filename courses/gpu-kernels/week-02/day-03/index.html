Handle Softmax Tails and Extremes

By the end of this hour

  • Validate softmax tails and extreme finite logits.
  • Turn numerical failures into a precise supported-input contract.

Before you begin

  • The working small-row Triton softmax.
  • Your frozen shape and value matrix from 3-1.

Environment or workflow question? Day 0 handbook.

The key idea

Padding a row for a reduction changes the computation unless invalid lanes are neutral for every operation. For softmax, negative-infinity padding must be excluded from the maximum and yield zero probability mass. Finite rows with large common offsets are a useful stability test: the result should depend on differences, not the absolute offset, within the representable precision of the input. Equal logits should produce a uniform distribution. Width one should produce one. These invariants often locate a bug faster than a single aggregate error statistic, especially when an incorrect mask affects only the last program lanes.

Your 60-minute plan

  1. Retrieve

    5 min

    Predict the exact softmax result for width one and for a row containing N identical finite values.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Re-read K3’s masked-load and reduction logic. Trace the last valid and first invalid lane for width 33 and block width 64.

  3. Build

    35 min

    Run the entire frozen matrix, including widths on both sides of powers of two. Add explicit assertions for finite outputs, nonnegative probabilities, row sums, width-one output, and repeated-logit uniformity. Compare random rows and large finite offsets against the stable FP32 reference, accounting for rounding already present in the input. If a case fails, print one failing row and inspect its mask and denominator before changing tolerances. Document a justified FP32 error threshold and mark nonfinite inputs or unsupported widths as rejected, not silently accepted.

  4. Verify and save

    10 min

    Save a per-case error table and the final support contract. Re-run the original small cases after any fix to ensure tail handling did not change their results.

What to save

Tail and extreme-logit cases pass without unexplained nonfinite values.

Watch for: Do not loosen a global tolerance to conceal a single tail-indexing error.

Check your understanding

Why can adding a very large constant change the computed probabilities even with stable softmax?

Check your reasoning

The input dtype may round away small differences before softmax runs; max subtraction cannot recover information already lost in the stored inputs.
