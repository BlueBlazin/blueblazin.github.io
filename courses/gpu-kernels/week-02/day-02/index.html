Implement Triton Softmax Reductions

By the end of this hour

  • Implement one Triton program per softmax row.
  • Keep max, exponentials, and denominator reductions in FP32.

Before you begin

  • The frozen softmax contract and reference from 3-1.
  • Working Triton environment on the NVIDIA GPU.

Environment or workflow question? Day 0 handbook.

The key idea

The first row-softmax kernel assigns a whole row to one program. Logical lane offsets cover a power-of-two block, while a mask distinguishes the actual width. Invalid lanes load negative infinity so they cannot increase the maximum and contribute zero after exponentiation. Convert loaded values to FP32 before the reduction, subtract the row maximum, exponentiate, sum, and normalize. This avoids writing intermediate arrays to global memory. Start with small exact block widths so that debugging concentrates on the reduction and row addressing; the next lesson deliberately probes tails and difficult numerical inputs.

Your 60-minute plan

  1. Retrieve

    5 min

    Write the input address for row r and column c of a contiguous M by N matrix.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read K3’s softmax kernel for row addressing, tl.max, tl.sum, and FP32 arithmetic. Then close the reference while implementing.

  3. Build

    35 min

    Create kernels/triton_softmax.py with a wrapper validating your declared shape and dtype contract. Launch M programs, one per row. Compute a power-of-two block width, load the row using its actual stride, convert to FP32, and perform max-subtracted exponentiation and normalization. Mask the output store. Begin with FP32 widths 8, 32, and 128 and row counts 1 and 4. Compare outputs with your stable PyTorch reference and record maximum absolute error plus row-sum error. Leave autotuning and wider rows for later investigation.

  4. Verify and save

    10 min

    Check every row independently, including a matrix with distinct rows so a row-offset error cannot hide. Save the implementation and small-shape error table.

What to save

Small-row outputs match the controlled-precision reference.

Watch for: Do not use the padded block width as the physical row stride; contiguous rows are separated by the actual width N.

Check your understanding

Why must invalid padded lanes load negative infinity rather than zero before the maximum?

Check your reasoning

Zero could incorrectly become the maximum for an all-negative valid row; negative infinity cannot affect its maximum and exponentiates to zero after finite rescaling.
