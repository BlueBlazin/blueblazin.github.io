Derive Online Softmax State Updates

By the end of this hour

  • Derive the running maximum, denominator, and weighted-sum recurrence.
  • Explain why previous state must be rescaled when a larger score arrives.

Before you begin

  • Your stable softmax derivation and the supplied dense causal-attention reference in fixtures/decoder.py.
  • Paper notes or a local notebook; no rented GPU is needed.

Environment or workflow question? Day 0 handbook.

The key idea

For one query, keep a running maximum m, a normalization sum ℓ\ellℓ, and a weighted value sum a. After a new score tile sss arrives:

mnew=max⁡(m,max⁡isi),α=em−mnew,pi=esi−mnew,ℓnew=αℓ+∑ipi,anew=αa+pV.\begin{aligned} m_{\mathrm{new}} &= \max(m,\max_i s_i),\\ \alpha &= e^{m-m_{\mathrm{new}}},\qquad p_i=e^{s_i-m_{\mathrm{new}}},\\ \ell_{\mathrm{new}} &= \alpha\ell+\sum_i p_i,\\ a_{\mathrm{new}} &= \alpha a+pV. \end{aligned}mnew​αℓnew​anew​​=max(m,imax​si​),=em−mnew​,pi​=esi​−mnew​,=αℓ+i∑​pi​,=αa+pV.​

The final output is a/ℓa/\ella/ℓ. Rescaling keeps old and new contributions in the same exponential coordinate system. This computes attention without retaining all scores, but the temporary score tile and the running output accumulator still require memory.

Your 60-minute plan

  1. Retrieve

    5 min

    Derive stable softmax for one complete row, then identify which quantities would be needed to combine two partial rows.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read K4’s online-softmax and IO-awareness explanation. Focus on the running-state recurrence rather than the full GPU implementation.

  3. Build

    35 min

    Create notes/kernels/online-softmax.md. Write the recurrence for one query and a value dimension D, labeling m and l as scalars, a as length D, scores as length B, and V as B by D. Work through scores [1,2,4] split after the second entry with simple two-dimensional values. Show explicitly why the old denominator and weighted sum need the same rescaling factor. Specify a safe initialization using the first nonempty valid tile, or equivalent guarded handling of m=-infinity, l=0, a=0. Do not implement the full attention kernel yet.

  4. Verify and save

    10 min

    Check the final manual result against dense softmax-weighted values in a tiny local calculation. Save dimensions, initialization, recurrence, and one worked example.

What to save

Written recurrence with dimensions and rescaling factors.

Watch for: Subtracting negative infinity from negative infinity in an empty tile produces an undefined value; initialization and fully masked tiles need an explicit policy.

Check your understanding

Why is rescaling only l but not a incorrect?

Check your reasoning

The numerator and denominator would represent different exponential scales, so their ratio would no longer equal the attention output.
