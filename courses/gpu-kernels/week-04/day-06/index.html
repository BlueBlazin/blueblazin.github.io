Validate Attention Recurrence and Memory

By the end of this hour

  • Validate causal blockwise attention across lengths and partitions.
  • Account separately for input, output, temporary tile, and running-state memory.

Before you begin

  • Your passing blockwise causal PyTorch reference.
  • The dense reference and saved recurrence derivation.

Environment or workflow question? Day 0 handbook.

The key idea

Online attention changes the memory schedule, not the definition of causal attention. Validation should therefore cover both numerical agreement and the information boundary: changing future keys or values must not change an earlier output. Sequence lengths just beyond a block boundary expose tails that exact multiples conceal. Memory accounting must state what is included. Q, K, V, and output remain linear in sequence length; a dense score matrix is quadratic. Temporary block scores and per-query-block state depend on tile dimensions. A Python prototype demonstrates this algorithmic storage pattern, but should not be advertised as an optimized GPU implementation.

Read the indicated section, not the entire source. The core reading fits inside the plan below. A video is an alternative to reading, not extra homework.

  • Core · 10 min · paper
    FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness

    IO-aware memory accounting; distinguish tiles from full scores.

Your 60-minute plan

  1. Retrieve

    5 min

    State the shapes of the score tile and weighted accumulator. Predict which allocation grows quadratically in dense attention.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Use K4’s IO and memory analysis to distinguish avoiding the full score matrix from eliminating every temporary allocation.

  3. Build

    35 min

    Freeze lengths 1, 3, 4, 5, 7, 8, and 9 with at least two legal tile choices. Check dense-reference agreement and finite outputs, then perturb future K/V positions and assert earlier query outputs remain unchanged. Include a late maximum in a score row and inspect any failed partition. Write a memory table for Q/K/V/output, dense scores, one score tile, and running m/l/a state using element counts and dtype bytes. Note whether processing one query block at a time changes the peak running-state allocation. Save the derivation and test command together.

  4. Verify and save

    10 min

    Verify all selected partitions and the future-perturbation check. Save reports/kernels/blockwise-attention.md, including exactly which memory quantities are estimates.

What to save

Dense-reference parity plus explained recurrence and memory savings.

Watch for: Do not present Python allocator measurements as proof of the eventual Triton kernel’s peak memory or speed.

Check your understanding

Does avoiding an N by N score tensor mean attention uses constant total memory?

Check your reasoning

No. Inputs and outputs still scale with sequence length, and temporary tiles plus running state consume memory; the avoided score storage is the quadratic part.

Specify Restricted Triton Attention Forward

By the end of this hour

  • Freeze a deliberately restricted attention-forward support contract.
  • Map the blockwise reference to Triton tiles and state variables.

Before you begin

  • The verified blockwise causal reference and recurrence notes.
  • A working Triton matmul plus the pinned NVIDIA environment.

Environment or workflow question? Day 0 handbook.

The key idea

Attention forward combines tile matrix products with online normalization, so a narrow first contract is valuable. Fixing one head dimension, contiguous layouts, one dtype, no dropout, and causal self-attention makes the implementation and validation attainable. A program can own one query block, keep its Q tile and FP32 online state, and walk over relevant K/V blocks. The temporary probability tile multiplies V to update the weighted accumulator. Numerical choices at that multiplication need explicit documentation, especially if probabilities are cast to a lower dtype for a tensor-core dot. Backward and general-purpose framework compatibility are outside this required exercise.

Resources for this hour

Read the indicated section, not the entire source. The core reading fits inside the plan below. A video is an alternative to reading, not extra homework.

  • Core · 10 min · tutorial
    Triton: Fused Attention

    Forward input layout and state ownership; skip backward.

Your 60-minute plan

  1. Retrieve

    5 min

    Write the dimensions of Q tile, K tile, score tile, V tile, and output accumulator for one program.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read K3’s fused-attention forward structure alongside K4’s recurrence. Focus on program ownership and state; skip backward and advanced scheduling.

  3. Build

    35 min

    Create notes/kernels/triton-attention-contract.md. Choose D=32, contiguous Q/K/V shaped B by H by N by D, FP16 inputs/output, FP32 normalization state, and causal attention without dropout. Initially fix B=H=1 and bound N to a small tested range such as 1 to 256. Choose supported query/key tile sizes from the pinned tutorial and draw their pointers and masks. State score scaling, probability-dot casting, and fully masked-row handling. Prepare exact-tile and later tail cases against your existing reference. Keep the support narrow enough to finish the forward implementation within its scheduled sessions.

  4. Verify and save

    10 min

    Check that every tensor and state has a dimension, dtype, and owner. Save the contract and planned validation cases without claiming the kernel is implemented yet.

What to save

Restricted support contract and tile/state mapping.

Watch for: A successful one-head prototype does not establish support for arbitrary batches, heads, layouts, or dropout.

Check your understanding

Why is fixing head dimension a reasonable first restriction?

Check your reasoning

It reduces the number of tile, layout, and numerical cases to debug while still exercising the full forward attention recurrence.
