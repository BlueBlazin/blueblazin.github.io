Environment or workflow question? Day 0 handbook.

The key idea

Vector addition exposes the smallest useful CUDA mapping: one thread computes one output element. For a one-dimensional launch, its global index is blockIdx.x times blockDim.x plus threadIdx.x. The host chooses enough blocks to cover the vector, so the kernel must guard indices outside the logical length. Neighboring threads access neighboring elements in this mapping, which gives a straightforward contiguous access pattern. The wrapper is part of the operator contract: it checks device, shape, dtype, and layout before a raw pointer reaches the kernel. This lesson implements only the minimal forward operation.

Your 60-minute plan

  1. Retrieve

    5 min

    Compute the global indices of threads 0 and 31 in block 2 when blockDim.x is 128.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Read K2 thread indexing and contiguous memory access guidance. Use the K3 vector-add tutorial only to compare the operation’s input/output contract. Confirm the compiler prerequisites in the official PyTorch C++/CUDA extension documentation before trying to build.

  3. Build

    35 min

    Create kernels/cuda_vector_add.cu and a small Python-facing wrapper following your pinned framework extension example. Use one-dimensional indexing, a block size such as 128, and a guarded write z[i] = x[i] + y[i]. Allocate the output in the wrapper, validate equal-length contiguous CUDA FP32 inputs, and launch on the framework’s current stream. Begin with length 256 and print the first few reference/output values. Keep compilation outside any later timer. Save a sketch relating blocks to indices; do not add shared memory, vectorized loads, or tuning.

  4. Verify and save

    10 min

    Compare the complete output with x + y for the small supported input. Record the build command and explain the index of the last valid element.

What to save

CUDA launch and indexing explained for a small contiguous vector.

Watch for: A raw default-stream launch can violate framework stream expectations; use the current-stream mechanism from the pinned extension example. If the toolchain is missing, save the failure and use scheduled setup/flex time; stop an idle paid GPU.

Check your understanding

Why does vector addition need no synchronization between threads?

Check your reasoning

Each thread reads its own input elements and writes a distinct output element; there is no cross-thread dependency.
