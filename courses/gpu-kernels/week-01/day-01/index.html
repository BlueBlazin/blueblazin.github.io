Model GPU Indexing and Memory Traffic Locally

By the end of this hour

  • Distinguish CUDA threads, thread blocks, and device memory.
  • Predict which decoder operations depend most on memory traffic or arithmetic.

Before you begin

  • A working Python interpreter and a text editor; no PyTorch installation or GPU rental is needed for this first lab.
  • Use the tensor dimensions supplied in the exercise. The optional decoder fixture is introduced in Day0.

Environment or workflow question? Day 0 handbook.

The key idea

A CUDA kernel runs many threads grouped into blocks. Blocks can cooperate through shared memory and synchronization; ordinary blocks cannot assume a shared execution order. Registers hold thread-local values, while global device memory serves the whole grid. Coalesced access lets neighboring threads request neighboring addresses efficiently. A decoder combines large matrix multiplications with smaller reductions and elementwise operations. Large arithmetic count alone does not identify the slowest operation: bytes transferred, launch overhead, available parallelism, and intermediate allocations also matter. Today you are making testable predictions, before renting time to measure them.

Your 60-minute plan

  1. Retrieve

    5 min

    Without notes, list the tensors read and written by a linear layer, softmax, and normalization.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Use K1 for execution and memory diagrams, then K2 for coalesced access and arithmetic intensity. Stop after these concepts.

  3. Build

    35 min

    Write a small pure-Python shape-and-traffic calculator. For vector addition at N=129, calculate valid global indices for blocks of 128 and the FP32 read/write payload. For a linear layer with M=32, K=64, N=256, calculate output shape, 2MKN2MKN2MKN FLOPs and the ideal input/output bytes. Then model one attention score matrix for B=1, H=4, T=32, D=16 and compare its element count with Q/K/V. Print a three-row table and assert the vector payload is 12N12N12N bytes. Sketch threads, blocks, registers, shared memory and global memory. End with one bottleneck hypothesis for each operation. This executes useful indexing and memory reasoning locally; do not install CUDA or start a paid instance.

  4. Verify and save

    10 min

    Check that every arrow names a memory space and every prediction has a measurable consequence. Save the diagram and prediction table.

What to save

A working local calculator, dimensioned table and three bottleneck hypotheses.

Watch for: Do not assume a GPU block is a physical multiprocessor or that every block executes simultaneously.

Check your understanding

Why might a cheap elementwise operation matter in a small decoder?

Check your reasoning

It can be limited by memory movement or launch overhead; few arithmetic operations do not guarantee low elapsed time.
