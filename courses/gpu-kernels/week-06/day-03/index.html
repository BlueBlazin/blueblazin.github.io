Integrate RMSNorm Into the Decoder

By the end of this hour

  • Swap RMSNorm through one decoder configuration switch.
  • Check model-level loss and gradient equivalence.

Before you begin

  • A registered differentiable RMSNorm with explicit fallback behavior.
  • The supplied decoder fixture, its norm_factory(width, eps) module factory, fixed synthetic tokens/targets, and saved deterministic random state dict.

Environment or workflow question? Day 0 handbook.

The key idea

Operator-level agreement does not guarantee integration-level agreement: the decoder may normalize a different axis, flatten rows differently, use another epsilon, or cast weights at a different point. A single configuration switch makes the reference and custom paths share all other code. Compare both models from identical parameters and random state, with stochastic behavior disabled or controlled. Loss is a useful summary but can hide local errors, so also inspect representative parameter gradients and the normalization inputs. A short matched step is sufficient here; a new training campaign is unnecessary.

Your 60-minute plan

  1. Retrieve

    5 min

    Find every RMSNorm call in the decoder and write the expected leading dimensions at those points.

  2. Study

    10 min

    Use the core resources above for ten minutes in total, focusing only on the indicated sections. Revisit K5 composition guidance and your decoder normalization configuration; identify where flattening and dtype conversion occur.

  3. Build

    35 min

    Connect the decoder fixture’s norm implementation hook to your checked RMSNorm wrapper, preserving the supplied reference path. Instantiate two tiny models from the same state dict and feed the same fixed batch with dropout disabled or identically controlled. Run forward, loss, and backward once for each path. Compare loss, selected logits, RMSNorm weight gradients, and one attention and feedforward parameter gradient. If the decoder shape exceeds the restricted kernel contract, exercise the declared fallback or use a smaller valid test configuration; do not silently expand kernel support. Save the complete comparison configuration with the results. Use the actual fixture interface: norm_factory(width, eps) returns an nn.Module whose weight parameter is named weight and whose forward(x) calls your registered rmsnorm(x, weight, eps), flattening leading dimensions and restoring the original shape. Pass that factory to create_fixture or TinyDecoder. Preserve the incoming epsilon (the fixture defaults to 1e-5) and validate the configured feature width (64 by default), rather than hard-coding the earlier standalone exercise settings.

  4. Verify and save

    10 min

    Record numerical errors and which calls used the custom path versus fallback. Keep the same deterministic random state dict and synthetic batch for profiling next session.

What to save

Decoder training-loss and gradient parity with the reference path.

Watch for: Comparing two independently initialized decoder instances.

Check your understanding

Why might close losses still conceal an integration bug?

Check your reasoning

Loss compresses many outputs into one scalar; local discrepancies or compensating errors can remain visible in logits and parameter gradients.
